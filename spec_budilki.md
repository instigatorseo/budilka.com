### 2.3. Жизненный цикл будильника

**Установка (Старт):** время → `Date` на сегодня (секунды=0); если уже прошло → +1 день; hash обновляется (§3); строка состояния появляется; заголовок вкладки = `<время> - <заголовок>`; `localStorage.alarmHash` сохраняется; разблокировка звука (первый play в обработчике клика); включение keep-awake (§5.3).

**Срабатывание (условие: `alarmTime <= now`, проверка каждую секунду):**
1. Модалка `#dialog-alarm`: иконка будильника + заголовок + крупное время.
2. Проигрывается выбранный звук (с повтором, если включён).
3. Заголовок вкладки **мигает**: `*** 16:50 - БУДИЛЬНИК ***` ↔ исходный, переключение каждую 1 с (setInterval) — работает и в фоне.
4. В hash добавляется `enabled=0` (при F5 не пересрабатывает).
5. Через 60 с звонка в диалоге появляется «Просрочено: ЧЧ:ММ:СС» (обновляется).
6. **OK**: звук стоп, мигание стоп, строка состояния скрывается.
7. «Выключить будильник» в строке состояния — отмена до срабатывания.

**Режим embed** (страница внутри iframe): вместо модалки — фон панели мигает красным 4 раза, звук играет 8 с и всё сбрасывается автоматически.

### 2.5. Автомасштабирование часов (алгоритм из оригинала)

- Массив фиксированных размеров `FONT_SIZES[0..N]`, текущий индекс `alarmFontSizeId`.
- Функция подбора: вычислить суммарную высоту `m()` (часы + заголовок + дата + строка будильника + отступы) и ширину `s()`; цикл: пока `m() > доступнаяВысота || s() > доступнаяШирина` — уменьшать размер; пока есть запас и размер < целевой пользователя — увеличивать. Защита: минимум `MIN_FONT_SIZE`.
- Пропорции: AM/PM ≈ шрифт/3 (digital: /1.3); дата и заголовок будильника ≈ max(шрифт/3, 24–32px); обратный отсчёт ≈ max(шрифт/6, 14px).
- Центрирование часов по вертикали/горизонтали с учётом панели инструментов; при ресайзе — пересчёт (с дебаунсом 100–1000 мс).
- Кнопки A± меняют только пользовательский уровень (сохраняется), визуально скрываются/дизейблятся на границах.

## 4. Таймер, Секундомер, Точное время

### 4.1. Таймер `/timer/`

**Экран:** большие цифры `00:05` (ЧЧ:ММ или ММ:СС по длительности) + кнопка «Установить таймер»; при запуске — «Стоп»/«Старт» (пауза), «Сброс». Строка состояния: заголовок, обратный отсчёт, «Выключить таймер».

**Модалка «Изменить таймер» (`#form-timer`):**
- **Режим** (радио, на десктопе): «Обратный отсчет» / «Отсчитывать до (от) даты и времени». На мобильных — переключатель «Дата и время».
- **Обратный отсчёт**: Час (0–99!) / Мин (0–59) / Сек (0–59), selects с кнопками ±.
- **При достижении нуля** (радио): «Остановить таймер» / «Повторный запуск таймера» / «Выполнять как секундомер (по возрастающей)».
- **Дата и время**: datepicker (min view = месяц) + timepicker.
- **Звук** (те же 21 + свой файл + Повторить), **Заголовок** + чекбокс «Показать сообщение» (показывать ли модалку при срабатывании).
- Кнопки: **Тест** / **Отмена** / **Старт**.

**Поведение при срабатывании:** то же, что у будильника (модалка + звук + мигающий заголовок), если «Показать сообщение» включено.

**SEO-блоки под инструментом:**
- «Поставить таймер на определенное время»: `/таймер-на-N-минут(ы|у)/` (1, 3, 5, 10, 15, 20, 30, 40, 45, 60 минут; 10, 20, 30, 45, 60, 90 секунд; 1, 2, 4, 8 часов).

### 4.2. Секундомер `/sekundomer/`

**Экран:** `00:00.00` + кнопки:
- `Сброс` (disabled, пока не запущен/не остановлен), `Старт` → при работе `Стоп`; при работе появляется `Круг` (всё — 4 отдельные кнопки `#btn-reset`, `#btn-resume`, `#btn-pause`, `#btn-lap`, переключаются видимостью).
- Список кругов `#pnl-laps` → таблица `#tbl-laps`: колонки «Круг | Время | Общее время».
- Время живёт в заголовке вкладки: `00:25 - Секундомер онлайн`.
- **Точность до миллисекунд**, при больших значениях показывает дни (формат из настроек).

**Настройки (отличие от главной):** вместо «Показать секунды» — «Формат времени»: `00:00.000` / `00:00.00` / `00:00.0` / `00:00`.

**Сохранение:** показания и круги переживают закрытие/перезагрузку (hash `#start=…&laps=…` + localStorage); ссылку можно шарить.

**Алгоритм точности:** счёт идёт от `Date.now()` минус `startMs` (никакого инкремента); отображение обновляется через rAF/тик 1 с; «Круг» фиксирует текущее значение.

## 5. Надёжность срабатывания будильника (P1 — критично)

### 5.1. Что делает оригинал

1. **Проверка каждую секунду**: `alarmTime <= now` (не `==`!) — при «проснувшемся» с опозданием таймере будильник сработает поздно, но сработает.
2. **Мигающий заголовок вкладки** (setInterval 1 с) — видимый сигнал из фоновой вкладки.
3. **Самокалибрующийся тик** (§2.7) — нет дрейфа.
4. **Контроль запуска звука** на мобильных (опрос currentTime каждые 10 мс) + `.catch` на всех `play()`.
5. **Автостоп звука** через 10 мин; автоплей-разблокировка первым кликом.
6. **Модуль `vNoSleep` написан, но НЕ вызывается** в собранном сайте (проверено: при установленном будильнике в DOM нет ни одного audio/video, `NoSleep` не загружается). Т.е. оригинал никак не мешает браузеру троттлить/замораживать фоновую вкладку.

### 5.2. Слабые места оригинала (что улучшаем)

- Chrome троттлит фоновые вкладки (таймеры до 1/мин, при интенсивном режиме — реже; при экономии энергии вкладка может быть заморожена вовсе).
- Выключенный экран телефона = остановка вкладки (без NoSleep/Wake Lock).
- Нет Web Worker, нет Wake Lock API.

### 5.3. Обязательный набор для нашей копии

1. **Точный расчёт цели**: `targetMs` = ближайшее будущее HH:MM:00; каждый тик `remaining = targetMs - Date.now()` (пересчёт, не декремент).
2. **Двойной механизм запуска** («кто первый»):
   - точный `setTimeout(fire, remaining)` (с повторной проверкой при вызове, т.к. таймер может сработать раньше);
   - сторожевой тик 1 раз/с: `alarmTime <= now → fire` (ловит момент, если точный таймер был троттлен).
3. **Web Worker**: раз в 500–1000 мс шлёт сообщение, главный поток сверяет `Date.now() >= targetMs`. Worker меньше троттлится и не блокируется рендером.
4. **Wake Lock API** (`navigator.wakeLock.request('screen')`) при установке; перевзятие по `visibilitychange`→visible и по событию release.
5. **Fallback «тихий звук»** (десктоп): при установке — скрытый `<audio loop src="noise.ogg">` (тихий шум); играет, когда вкладка скрыта (`visibilitychange`), паузится при возврате. Играющий звук — официальный сигнал браузеру не замораживать вкладку.
6. **NoSleep.js** (iOS/Android): скрытое `video/webm` в цикле — единственный способ не дать iOS заснуть при выключенном экране. Включить при установке, выключить при выключении будильника. Ленивая загрузка скрипта.
7. **Пересчёт при пробуждении**: `visibilitychange`→visible и `focus` → немедленная проверка `Date.now() >= targetMs → fire`.
8. **Аудио-устойчивость**: первый `play()` — в обработчике клика «Старт»/«Тест»; при отказе — ретрай каждые 2 с, пока открыт диалог звонка; контроль реального старта (currentTime) на мобильных.
9. **Мигающий заголовок вкладки** — резервный канал.
10. **Vibration API** при срабатывании (если включено).
11. **Честные ограничения** (выводить пользователю): не сработает при закрытой вкладке/браузере, выключенном ПК, сне ОС, закрытом Safari на iOS. Предупреждение на странице + подсказка при установке.

### 5.4. Чек-лист жизненного цикла

```
onStart():  targetMs; hash+localStorage; audioUnlock(); keepAwake.enable()
            (WakeLock + noise.ogg + NoSleep + Worker); setTimeout(fire, remaining);
            watchdog 1 c; title = "16:50 - Название"
onFire():   if (alreadyFired) return; модалка; play(звук, loop); vibrate;
            мигающий title; hash += enabled=0
onStop():   стоп звука; keepAwake.disable(); worker/timers сняты;
            title восстановлен; строка состояния скрыта
```

| № | Тест | Ожидание |

# ЧАСТЬ II. АЛГОРИТМ ВОСПРОИЗВЕДЕНИЯ (для программиста)

## 6. Стек: WordPress + шорткоды

**Сайт делается на WordPress. Весь функционал — через шорткоды на страницах.** Это полностью осуществимо: все инструменты — клиентский JS, которому безразлично, кто отдал HTML (статический файл или WP). WordPress через шорткод печатает те же контейнеры (`#pnl-main`, `#form-alarm` и т.д.) и подключает те же JS/CSS. **Надёжность срабатывания будильника от WordPress не зависит вообще** — она определяется браузером и нашим JS (§5.3): страница после загрузки живёт в браузере, WP в этот момент уже не участвует.

### 6.1. Плагин `budilki` (весь код — в нём)

```
wp-content/plugins/budilki/
  budilki.php               — регистрация шорткодов, enqueue, генератор страниц
  includes/generator.php    — массовое создание SEO-страниц (wp_insert_post)
  assets/css/style.css      — порт css/style.css оригинала
  assets/js/lang.js         — словарь строк
  assets/js/main.js         — общее: часы, настройки, шаринг, keep-awake, звук
  assets/js/alarm.js        — будильник; timer.js; stopwatch.js; time.js
  assets/js/worker-alarm.js — worker надёжности (§5.3)
  assets/sound/*.mp3, assets/sound/noise.ogg
  assets/lib/nosleep.min.js
  assets/font/, assets/img/
```

### 6.2. Шорткоды

Один базовый шорткод с параметрами (регистрируется в `init`):

| Шорткод | Что рендерит |
|---|---|
| `[budilki tool="alarm"]` | Полный будильник (главная) |
| `[budilki tool="alarm" time="04:00"]` | Будильник с предустановкой (SEO-лендинг `/будильник-на-4-00/`): в `data-alarm-time` + кнопки «Тест»/«Изменить» |
| `[budilki tool="timer" duration="60"]` | Таймер (duration в секундах — для лендингов `/таймер-на-1-минуту/`) |
| `[budilki tool="stopwatch"]` | Секундомер |
| `[budilki tool="time"]` | Точное время со списком городов |
| `[budilki tool="city" city="Москва" tz="Europe/Moscow"]` | Страница города `/time/<город>/` |
| `[budilki tool="holiday" name="Новый год" date="2027-01-01" pinned="1"]` | Счётчик «сколько дней до» (`/timer/<праздник>/`). Без `pinned` дата «плавающая»: JS сам перекатывает на следующее наступление даты |
| `[budilki tool="holidays-hub"]` | Хаб `/prazdniki/`: таблица праздников с «N дн.» |

Шорткод выводит HTML-каркас инструмента + `<script>` инициализации с параметрами. Один и тот же шорткод на разных страницах = разные инструменты; SEO-текст и H1 пишутся обычным контентом страницы в редакторе.

### 6.3. Правила работы с WordPress (важно!)

1. **Подключение ассетов только на нужных страницах**: на хуке `wp_enqueue_scripts` проверять `has_shortcode(get_post()->post_content, 'budilki')` — чтобы JS/CSS не грузились на всём сайте. Версия файлов — `filemtime()` для сброса кэша.
2. **jQuery в noConflict**: WP отдаёт jQuery в noConflict-режиме (`$` занят). Писать JS в IIFE `(function($){...})(jQuery)` либо нативный JS. Свою jQuery-версию НЕ подключать (конфликты с ядром/админкой).
3. **Чистый шаблон страницы**: для страниц-инструментов нужен template «Blank» (без сайдбара, без заголовка темы, полная ширина), иначе вёрстка часов ломается. У залогиненных пользователей не должно мешать wp-admin-bar (в blank-шаблоне убрать).
4. **Кэширующие плагины**: HTML страницы статичен — кэшировать можно смело; состояние живёт в hash/localStorage и кэш его не трогает. Исключить из минификации инлайн-скрипт инициализации (пометить `data-no-minify` / исключить в настройках плагина кэша).
5. **Никаких автообновлений страницы** (нет редиректов, ajax-перезагрузок) — иначе сбросится будильник.
6. **Cyrillic URL работают в WP нативно**: страница-родитель «timer» (слаг `timer`) + дочерние `новый-год`, `новый-год/2027`; «time» + дочерние города; верхнеуровневые `будильник-на-4-00`. URL получаются 1:1 как у оригинала.
7. **Embed-режим** (виджет «HTML-код» для чужих сайтов): отдельная страница не нужна — JS сам определяет `window.self !== window.top` и скрывает SEO-блоки/шапку (как `isEmbed` в оригинале).
8. **SEO-мета** (title/description/OG/canonical): через любой SEO-плагин (Rank Math/Yoast) либо хук `wp_head` в нашем плагине, читая мета страницы. Каноникал — только чистый URL без hash.
9. **WP-Cron или ручной запуск генератора** — для пересоздания/обновления SEO-страниц (например, ежегодный ролл дат в title «Когда Новый год 2027»).
10. Тяжёлые сторонние плагины на сайт не ставить — лишний JS может конфликтовать с тиком часов (минимум: SEO-плагин + кэш).

### 6.4. Генератор SEO-страниц (`includes/generator.php`)

Массовое создание страниц через `wp_insert_post` из массивов данных:

- **Лендинги будильника**: `[4:00, 4:30, 5:00, … 14:00]` → страницы `/будильник-на-H-MM/`, контент = `[budilki tool="alarm" time="H:MM"]` + 2–3 уникальных абзаца.
- **Лендинги таймера**: `[1м, 3м, 5м, 10м, 15м, 20м, 30м, 40м, 45м, 60м, 10с, 20с, 30с, 45с, 60с, 90с, 1ч, 2ч, 4ч, 8ч]` → `/таймер-на-N-…/`.
- **Праздники**: массив `{название, слаг, дата|функция-вычисления (пасхалия)}` → `/timer/<слаг>/` + дочерние `/timer/<слаг>/<год>/` на 2026–2035.
- **Города**: массив `{город, страна, слаг, tz}` (IANA) → `/time/<город>/`.
- Каждой странице: `post_title`/H1, уникальный текст, SEO-мета, шаблон Blank, правильный `post_parent`.

Антидубль: перед созданием проверять `get_page_by_path`; слаги уникальны по дереву страниц. Генератор идемпотентен (повторный запуск не плодит копии).

**Надёжность будильника на WP**: требования §5.3 не меняются ни на йоту — Wake Lock, noise.ogg, NoSleep.js, Worker, пересчёт при пробуждении — это всё JS в плагине, работает идентично статике.

5. i18n: все строки в `assets/js/lang.js` (словарь) — чтобы позже добавить языки; тексты страниц — в WP.
6. Аналитика: своя (Метрика/GA4); рекламу оригинала не переносить.
7. WordPress: минимум плагинов (SEO + кэш + наш `budilki`); blank-шаблон для страниц-инструментов; noConflict-режим jQuery; никаких JS-конфликтов в консоли на страницах инструментов; WP-Cron-задача/скрипт ежегодного обновления дат в SEO-страницах.
8. Кэширование: статический HTML можно кэшировать агрессивно; исключить инлайн-скрипт инициализации из минификации.

## 10. Приложение: ключевые факты из разбора

- Движок vClock v2.3 (jQuery + Bootstrap 3.3.7), всё статично, состояние — hash + localStorage (+ IndexedDB для своего звука).
- Точка инициализации: `$(function(){ vAlarm.init(); App.init(); })`; скрипты: jquery → lang → main → alarm.
- Логика будильника: tick `h()` (§2.7) + проверка `alarm.time <= now` раз в секунду → модалка `#dialog-alarm` + звук + мигающий title `*** 16:50 - БУДИЛЬНИК ***` + `enabled=0` в hash; просрочка «Просрочено: …» после 60 с.
- Keep-awake оригинала: `vNoSleep` (noise.ogg на десктопе, NoSleep.js на мобильных) **определён, но нигде не вызывается** — проверено вживую (при установленном будильнике в DOM нет ни одного media-элемента). Наша копия обязана его включить + добавить Wake Lock и Worker (§5.3).
- Секундомер: состояние в hash (`#start=ISO&laps=мс.мс`), время в title вкладки, круги в таблице «Круг | Время | Общее время», 4 формата долей.
- Таймер: режимы «обратный отсчёт»/«до даты-времени», «при нуле»: стоп/рестарт/секундомер, часы до 99, чекбокс «Показать сообщение», hash `#countdown=HH:MM:SS`.
- Точное время: список городов со смещением «Сегодня, -7 Ч», каталог `/time/<город>/` на сотни городов, title `Точное время в <городе>, <страна>`.
- SEO-счётчики: `44 дн. 07:10:40` + H1 + «Пт - 1 января 2027» + текст + блок годов 2026–2035.
- Звуки: `/sound/<код>.mp3` × 21, цикл автостопится через 10 мин (`audioPlayDuration=600000`).
- localStorage: `alarmHash`, `alarmAudioCode`, `alarmAudioLoop`, `alarmFontSizeId`, `themeNightMode`, `themeColorId`, `clock12hour`, `clockDateVisible`, `clockSecondsVisible`, `themeDigitalFont`, `audioCustomName`, `audioFile`, `alm0`–`alm9`, настройки списка городов.
- `data-utc` (серверная unix-метка в `#pnl-main`) — в оригинале не используется; в копии можно применить для коррекции системных часов.
